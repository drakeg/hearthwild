## Acceptance criteria

**HW-131: Mad Mallard standards.** *As the Product Owner, I want this repository to follow my standard layout and automation, so that any person or agent can pick it up and ship safely.*
- Root `AGENTS.md`, `SPRINTS.md`, `BACKLOG.md` (moved from `docs/agile/`), `RELEASES.md`, alongside the existing `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md` and `CHANGELOG.md`. The standards toolkit's audit reports nothing missing.
- **CI** (`.github/workflows/ci.yml`) on every push and PR: syntax check, all tests, and a Docker Compose build that must start and answer.
- **Security:** CodeQL scanning on PRs, on `main` and weekly. Renovate already keeps dependencies current.
- **Local and LAN testing:** `Dockerfile` and `compose.yaml` serve the game on port 4180 to the whole network, with the world in its own volume.
- **Badges** under the README title, generated by the standards toolkit and only claiming what the repo proves; dynamic where possible (workflow status, release, release date, downloads, license, issues, PRs, activity).

**HW-133: README rewrite.** The README describes the game as it is now: features, controls, hosting (app, Docker, source), saves and recovery. It drops old version numbers and outdated limits.

**HW-122: Free demo build.** See the [backlog](../../../BACKLOG.md).
